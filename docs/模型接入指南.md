# 模型接入指南（详细版）

应用内置两个演示引擎，无需模型即可跑通全部流程。要获得真实的“音色克隆 / 转换”效果，按本文接入 GPT-SoVITS 与 RVC。

**两条路径**：

| 功能 | 需要安装 | 用在哪 |
| --- | --- | --- |
| 克隆朗读（TTS） | GPT-SoVITS | “文字转语音”页，用你的音色朗读文字 |
| 音色转换（VC/实时） | RVC | “声音转换”页、“实时变声”页，把你的声音变成目标音色 |

---

## 一、GPT-SoVITS（克隆朗读）

### 方式 A：整合包（推荐，最省事）

1. 打开 GPT-SoVITS 官方仓库 Release 页：
   `https://github.com/RVC-Boss/GPT-SoVITS/releases`
2. 下载最新的 Windows 整合包（自带 Python 环境与模型权重，解压即用）。
3. 解压后，**启动 API 服务**（在整合包根目录打开 PowerShell）：
   ```powershell
   .\runtime\python.exe api.py -a 127.0.0.1 -p 9880
   ```
   保持这个窗口开着（首次运行会加载模型，等出现 `Uvicorn running on http://127.0.0.1:9880` 即就绪）。

### 方式 B：源码安装

1. 克隆仓库到本机：
   ```powershell
   git clone https://github.com/RVC-Boss/GPT-SoVITS.git models\gpt_sovits
   cd models\gpt_sovits
   pip install -r requirements.txt
   ```
2. 按仓库 README 下载 GPT-SoVITS v2 预训练权重，放入：
   - `GPT_SoVITS/pretrained_models/`（vits 模型）
   - `GPT_SoVITS/pretrained_models/gpt/`（GPT 模型）
   - `GPT_SoVITS/pretrained_models/chinese-hubert-base/` 与 `chinese-roberta-wwm-ext-large/`
3. 启动 API：
   ```powershell
   python api.py -a 127.0.0.1 -p 9880
   ```

### 配置应用

1. 打开应用 → **设置** → GPT-SoVITS 卡片。
2. 只填 **API 地址**（默认 `http://127.0.0.1:9880` 已是正确值，确认没改过即可）。
   - ⚠️ “代码目录 / 服务脚本”**建议留空**。应用自动启动 `api.py` 用的是应用自己的 Python，而 GPT-SoVITS 的依赖装在它自己的环境里，自动启动极易失败。手动启动 API 窗口最稳。
3. 点**保存设置**。设置页底部“引擎状态”应显示 `TTS：GPT-SoVITS（AI 克隆）— API 已连接：...`。

### 使用

1. **克隆音色**页：导入一段 **5~30 秒干净人声**（无音乐、无噪声），保存到音色库。
2. 在音色库里选中该音色 → **重命名**旁没有编辑入口，参考文字在导入时的对话框填写（或重新导入时填）。参考文字 = 这段音频说了什么，逐字准确能显著提高克隆稳定性；留空也能用，效果略差。
3. **文字转语音**页：选择该音色 → 输入文字 → 生成。生成的声音应明显像参考音频。

## 二、RVC（音色转换 / 实时变声）

### 1. 安装 rvc-python（装到应用的 .venv）

先给应用环境装 CUDA 版 PyTorch（RTX 4060 用 CUDA 12.1，约 2.5GB）：

```powershell
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cu121
.\.venv\Scripts\python.exe -m pip install rvc-python
```

> 如果安装 torch 时没有走 CUDA 源，会装成 CPU 版，实时变声会卡到不可用。装完确认：
> ```powershell
> .\.venv\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
> ```
> 输出 `True` 才正确。

### 2. 获取模型（.pth，二选一）

**方式 A：下载现成模型**
- 找公开的 RVC 模型文件（`.pth`），如 HuggingFace / 各模型分享站上你已获授权的音色模型。
- 下载到任意目录，记住路径。

**方式 B：自己训练（用 RVC WebUI）**

1. 下载 RVC WebUI：`https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI`（有整合包）。
2. 准备 **3~10 分钟干净人声**（去噪、去掉长静音、最好裁剪成 10 秒左右一段的多个片段）。
3. 打开 WebUI，按顺序跑：
   - **1-数据预处理**：选择数据集目录 → 处理
   - **2-提取特征**：自动提取 hubert 特征与 f0
   - **3-训练**：设置实验名，训练到损失不再明显下降（几十分钟到几小时，4060 上小模型约 1~2 小时够用）
   - **4-训练（重训练/导出）**：导出 `xxx.pth`；特征索引 `.index` 在预处理时已生成
4. 记住 `.pth` 与 `.index` 的路径。

### 3. 配置应用

1. 打开应用 → **设置** → RVC 卡片。
2. 填写：
   - **模型文件**：`.pth` 的完整路径（必填）
   - **索引文件**：`.index` 路径（可选，建议填，提升音质）
   - **F0 算法**：默认 `rmvpe`（效果最好）；唱歌用 `crepe`
   - **默认升调 / 索引比率**：保持默认即可
3. 点**保存设置**。设置页底部应显示 `VC：RVC（AI 音色转换）— rvc-python 模式（GPU/CPU）`。
4. （可选）此时音色库中**所有非演示音色**都会走 RVC 转换；音色名只作为历史记录标识，不影响用哪个模型（全局只配了一个模型）。

### 使用

- **声音转换**页：选择音色 → 上传/录制你的声音 → 开始转换。
- **实时变声**页：选择音色 → 选输入/输出设备 → 打开“变声”开关。首次启动会加载模型（几秒~几十秒），加载后应能实时听到变声。

## 三、验证清单

- **GPT-SoVITS**：设置页状态显示“API 已连接” → TTS 用克隆音色生成 → 声音有明显相似度。
- **RVC**：设置页状态显示“rvc-python 模式” → VC 页转换输出非空 → 实时页能听到变声。
- 隐私：全部处理在本机完成，应用不包含任何上传逻辑。

## 四、已知限制

- 应用自动启动 GPT-SoVITS `api.py` 用的是**应用自己的 Python**，与 GPT-SoVITS 环境不兼容，因此推荐手动启动 API（见上文）。
- 实时变声延迟受模型与分块大小影响，说话场景目标 ≤300ms；若明显卡顿，检查 torch 是否 CUDA 版，并优先用 `rmvpe`。

## 五、逐音色绑定 RVC 模型

设置页的“模型文件”是**全局默认模型**（所有音色共用）。若想让不同音色使用不同模型：

1. 打开**音色库**页，点音色卡片上的 **RVC 模型** 按钮。
2. 选择“绑定 / 更换 RVC 模型…”并指定该音色专属的 `.pth` 文件。
3. 绑定后卡片会显示“RVC · 模型：文件名”，声音转换 / 实时变声会优先使用该音色自己的模型。
4. 想回退到全局模型：点 **RVC 模型** 按钮 → “解除绑定（回退全局模型）”。

> 绑定只需选择 `.pth`，`.index` 索引仍使用设置页的全局配置。

## 六、多参考音频（GPT-SoVITS 多参考克隆）

音色卡片上的 **多参考** 按钮可为一个音色挂多条参考音频，每条独立填写台词，
生成时通过 v2pro API 的 `inp_refs` 参数传给模型，提升克隆稳定性与相似度：

- 主参考：该音色导入的 wav（台词在“参考文字”按钮或“多参考”对话框里填写）
- 附加参考：`Voice.extra_refs` 字段（JSON：`[{wav_path, prompt_text, prompt_language}]`），在“多参考”对话框添加/删除
- 请求组装：`app/engines/gpt_sovits.py::_synthesize_remote` 中 `inp_refs` 逐条携带路径与台词
- ⚠️ `inp_refs` 的 dict 字段名以 v2pro api 的 `handle()` 为准（当前实现用 `refer_wav_path/prompt_text/prompt_language`），若报 422/参数错误，需核对 api.py 中 `handle` 的解析逻辑
