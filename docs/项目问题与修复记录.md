## 1. 项目概况

Windows 本地桌面 AI 变声工具（PySide6，约 5300 行含测试）。功能：音色库 / 克隆音色 / 文字转语音(TTS) / 声音转换(VC) / 实时变声 / 历史记录 / 设置。

**引擎架构**：
- `app/engines/base.py`：Protocol（TTSEngine / VCEngine / RealtimeTransform）
- `app/engines/registry.py`：按"音色类型 + 引擎可用性"路由
- 演示引擎：`fallback_tts.py`（SAPI）+ `fallback_vc.py`（DSP 变调）——**不改变音色**
- 真实引擎：`gpt_sovits.py`（克隆 TTS，**已适配 v2pro API**）+ `rvc.py`（rvc-python / CLI）

**目录**：
```
app/core/   config voices validation audio_io dsp history jobs
app/engines base fallback_tts fallback_vc gpt_sovits rvc realtime registry
app/ui/     main_window + 7 pages + widgets theme context
tests/      21 个测试（core 层）
docs/       需求评审、模型接入指南、本文档
tools/      debug_import.py、debug_gpt_api.py、LaunchApp.cs（exe 启动器源码）
build_exe.cmd（编译 exe 用，Windows 自带 csc.exe）
```

## 3. 已完成：克隆朗读（GPT-SoVITS）✅

### 接入过程与关键修复

1. **下载 v2pro 整合包**（2025-06-04 版，自带 runtime + 权重）
2. **API 探测"未配置"问题**：`curl 127.0.0.1:9880` 返回 400，但应用探测失败
   - 根因：`urllib` 对 4xx/5xx 抛 **HTTPError 异常**而非返回响应，`except Exception` 兜底误判为失败
   - 修复：`gpt_sovits.py::_probe` 捕获 `urllib.error.HTTPError`，`exc.code < 500` 视为存活
3. **`/tts` 404**：v2pro 整合包 API **没有 `/tts` 路由**，合成走 **`POST /` + JSON body**
   - 适配：`_synthesize_remote` 重写为 JSON 请求，参数名对齐 v2pro（`refer_wav_path` / `prompt_text` / `prompt_language` / `text` / `text_language` / `speed` / `inp_refs` / `sample_steps` / `if_sr` 等）
   - 响应解析兼容：`_parse_audio_response` 支持 wav 二进制 / JSON base64 / JSON 文件路径三种
4. **代理问题**：`urllib` 默认走系统代理（Clash 等会把 127.0.0.1 请求转发），探测与合成均改用 `build_opener(ProxyHandler({}))`
5. **切 v3 权重**：整合包自带 `s2Gv3.pth` + `s1v3.ckpt`（模型版本 v3），比 v1 效果更好
   - 启动命令：`.\runtime\python.exe api.py -a 127.0.0.1 -p 9880 -s "GPT_SoVITS\pretrained_models\s2Gv3.pth" -g "GPT_SoVITS\pretrained_models\s1v3.ckpt"`
   - 已创建 **`start-api-v3.bat`**（整合包根目录）一键启动，双击即可
   - ⚠️ 命令行参数仅对本次启动生效；想永久改需改 api.py 的 `g_config` 配置文件

### 声音转换一直"转换中"（2026-08-06 已修复）✅

**现象**：点"开始转换"后按钮一直停在"转换中…"，无结果、无报错、不结束；任务管理器中 app 进程仍在。

**根因：exe 启动器管道死锁（stderr 4KB 管道写满）**

- `tools/LaunchApp.cs` 旧实现：`p.StandardOutput.ReadToEnd()` **阻塞到子进程退出**才返回，然后才轮到 `p.StandardError.ReadToEnd()`。
- 即应用运行期间 **stderr 从未被排空**，而 Windows 匿名管道默认缓冲区仅 **4KB**。
- RVC 首次推理要加载 hubert（fairseq 打印大量 INFO，实测单次全流程 stderr ≈ 5.6KB，其中 `HubertPretrainingTask/HubertModel Config` 大字典就超 4KB）→ 管道写满 → **python 写日志的线程永久阻塞**。
- 阻塞点恰在 `load_hubert()` 中途：`self.hubert_model` 永远为 None，后续每次 `vc_single` 都再走 `load_hubert` → 再次阻塞 → 转换永远不完成、无异常抛出（所以 JobQueue 的 error 回调不触发，界面一直"转换中"）。
- 证据：`app_launch.log` 最后一行恰好停在 `HubertPretrainingTask Config`（管道满的瞬间）；`data/tmp/tmpzm9w93x4/` 只有 `input.wav` 无 `output.wav`。
- 为什么之前 TTS 正常：GPT-SoVITS 走 HTTP 客户端，不打印大段日志，stderr 总量 < 4KB 从未触发。

**修复（双保险）**：

1. **`tools/LaunchApp.cs` 重写**：stdout/stderr 改用 `BeginOutputReadLine()/BeginErrorReadLine()` **异步持续排空**，管道永不写满；退出后 `WaitForExit()` 两次确保异步事件处理完，再统一写 `app_launch.log`。需重新编译 exe：`build_exe.cmd`（已重编译）。
2. **`app/main.py::_setup_logging()` 新增**：根 logger 只挂 **FileHandler**（`data/logs/app.log`），清掉 fairseq/rvc_python 装的 stderr handler；`warnings.filterwarnings("ignore")` 压掉 torch/fairseq 的 FutureWarning。即使将来在别的环境（管道不被排空）运行，日志也不再写 stderr。
   - ⚠️ 注意：`FileHandler` 是 `StreamHandler` 的子类，不能用 `isinstance(h, StreamHandler)` 过滤，否则会把文件 handler 也删掉（踩过）。

## 7. 技术要点与坑（全汇总）

- **整合包 runtime 是 `_pth` 隔离模式**（`runtime/python39._pth` 存在）：
  sys.path 只按 _pth 内容（python39.zip + `.`），**PYTHONPATH 与 users.pth 全不生效**！
  需要可导入的整合包路径必须写进 `python39._pth`（用相对路径 `..\`/`..\GPT_SoVITS`/`..\tools`，搬家也不怕）。
  现象：训练/脚本报 `No module named 'utils'/'AR'/'text'`，而 API 正常（api.py 在根目录，脚本目录恰在 path）
- **BERT 单条文本超 512 token（约 400+ 字）会崩 1-get-text**：`tensor a (9830) vs (512)`——超长素材需先切分
- **改字典行时逗号必须在引号后、注释前**：`"inp_text": r"...",  # 注释`，否则语法错误
- **新版 RVC WebUI（20260718）底模 emb_g 是多说话人预训练表，训练代码 strict 加载会继承**
  → 说话人条件失效（转换"不像"）。必须加载底模后重置 emb_g（train.py 补丁，见第 6 节）
- **RVC 无 f0（nono）模型 = 机器音**：训练时没勾 rmvpe 基频提取 → `if_f0:0` → nono 架构 → 音高全靠声码器重建。
  判断方法：看日志目录有没有 `2a_f0/2b-f0nsf`；推理类名 `SynthesizerTrnMs768NSFsid_nono`；导出 cpt 的 `f0` 字段为 0。
  修复 = 预处理勾 rmvpe + 训练页 if_f0 + `f0G40k.pth` 底模
- **RVC 音高差**：男声（~99Hz）转少女音（~340Hz）差 21 半音，无 f0 模型不改变输入音高且无法升调（f0_up_key 无效）；
  f0 模型可用升调（半音数 = 12×log2(目标/输入)）。应用音调滑杆已扩到 ±24
- **GPT-SoVITS 微调坑（2026-08-07）**：
  - 整合包从 D 盘搬到 E 盘后，`runtime/Lib/site-packages/users.pth` 里的绝对路径必须同步改，否则子脚本 `ModuleNotFoundError: text`
  - s2 训练 `pin_memory=True` 在 Windows 上偶发 `CUDA error: resource already mapped`（pin memory 线程崩溃）→ 改 `pin_memory=False`
  - s2 保存 checkpoint 前必须建好 `logs_s2_v2` 目录（WebUI 会建，命令行复刻时容易漏，报 `FileNotFoundError: G_xxx.pth`）
  - s2 在 8GB 显存 batch 16 OOM（报告 "13.39GiB allocated" 属 WDDM 计数异常）→ batch 4 + `grad_ckpt` + `PYTORCH_CUDA_ALLOC_CONF=max_split_size_mb:64`
  - s1 底模配对：**phoneme_vocab 732 配 gsv-v2final-pretrained 的 5kh 底模**，512 配 s1bert25hz-2kh（2kh 是 API 推理默认，配 732 配置会 size mismatch）
  - s1（24 层 transformer）batch 8 + max_sec 54 OOM → batch 2 + max_sec 30
  - s1 训练起不来可能是 `MASTER_PORT` 随机端口冲突（TCPStore 裸 RuntimeError）→ 已在 s2_train.py 固定为 39999
- **"转换像不像"不能用 log-mel 均值/hubert 均值判断**（对音色不敏感，全挤在 0.94~0.99）；
  用**波形相关度/逐帧余弦**（不同 sid 应 <0.5，同内容重复转换应 ~1.0）
- **UVR5 去混响可能损伤人声**（改变音色、加毛刺）——数据不脏时"只去伴奏"可能更好，可对比
- **RVC 训练数据量与效果**：3~10 分钟为下限，10 分钟+显著更好；游戏语音带后期处理（EQ/压缩/
  混响）→ 相似度有天花板，难以"一模一样"
- **RVC WebUI 端口**：默认 7865，被占或异常时可能变 7897（启动窗口会显示，浏览器连错端口报
  Connection errored out；训练任务结束后界面状态可能卡住 → F5 或重启 WebUI）
- **训练时别开其他 GPU 程序**（GPT-SoVITS 等抢显存，8GB 卡容易 OOM 崩溃）
- **新版 WebUI 模型 emb_g 是 (109, 256)（spk_embed_dim 被当说话人数）**：单说话人训练只有
  sid=0 有效，其余行随机；应用里 sid 保持 0

- **多音色 RVC 模型（n_spk>1）**：`cpt["weight"]["emb_g.weight"].shape[0]` = 说话人数；
  `vc_single(sid=...)` 选音色；`infer_file` 内部**写死 sid=0**，多音色必须直接调 `vc_single`。
  模型身份看 `cpt["info"]`（很多只有 epoch 数，无法识别是谁的音色）
- **RVC 训练素材下限 3~10 分钟干净人声**；游戏语音带混响/BGM 需先用 UVR5 分离人声；
  文件名不能有中文/括号（WebUI 预处理会出问题）；RVC 整合包自带训练，rvc-python 只有推理
- **Windows 匿名管道默认仅 4KB；子进程 stderr 不排空 = 写日志线程永久阻塞**（本次"转换中"根因）。启动器必须异步同时排空 stdout+stderr；日志量大时改文件
- **`FileHandler` 是 `StreamHandler` 的子类**：清 handler 时不能用 `isinstance(StreamHandler)` 过滤，否则文件日志也删掉

- **`QTimer.singleShot(0, fn)` 从后台线程调用 = 回调丢失**（无接收者重载在调用线程执行）——跨线程回调必须用 Qt 信号桥
- **urllib 对 4xx/5xx 抛 HTTPError**，探测存活要捕获并判断 `code < 500`
- **FastAPI StreamingResponse 生成器崩溃 = 客户端 IncompleteRead(0 bytes read)**：uvicorn 先发响应头再跑生成器，
  生成器 yield 前抛异常 → 连接关闭、0 字节 body。诱因是 API 进程跑太久内部状态损坏（重启即好），
  不是模型/音频/请求问题；排查方法：另起一个端口同参数实例对比，成功则说明旧实例坏了
- **urllib 默认走系统代理**——本地 API 用 `ProxyHandler({})` 绕过
- **v2pro 整合包 API 无 `/tts`**，用 `POST /` + JSON（字段名 `refer_wav_path` 等）
- **`threading.Lock` 不可重入**（嵌套死锁），用 `RLock`
- **rvc-python 实际锁 numpy<=1.23.5**（PyPI 查证，旧文档写 1.25.3 有误）；numpy 1.23 无 Python 3.12 wheel → 必须 Python ≤3.11，且需同步降 scipy（1.17 需要 numpy 2.x）
- **pip ≥24.1 拒绝旧 metadata**（omegaconf 2.0.6 的 `PyYAML>=5.1.*`）——降 pip<24.1
- **fairseq 0.12.2 无编译开关**：`FAIRSEQ_C_BUILD` 与 `--no-c-extension` 均不存在；跳过编译的唯一内置方式是环境变量 `READTHEDOCS=1`（副作用 dependency_links 指向 CPU torch，pip 24 已忽略该字段，无影响）。C 扩展（libbleu/data_utils_fast/token_block_utils_fast）都是函数内延迟导入，RVC 推理用不到，跳过安全
- **fairseq 0.12.2 / hydra 1.0.7 不兼容 Python 3.11**：dataclass 实例默认值报 `ValueError: mutable default`；且改 default_factory 后 fairseq `hydra_init()` 会读到 `dataclasses.MISSING` 哨兵 → 需打补丁（`tools/fix_fairseq_py311.ps1` 一键重打）
- **torch 与 torchaudio 必须同版本同 CUDA 代号**：rvc-python 的 `torchaudio>=2.0.0` 会让 pip 从 PyPI 拉最新 CPU 版，与 cu121 版 torch 不匹配 → `WinError 127 找不到指定的程序`；必须从 cu121 源装对应版本
- `QFileDialog.getOpenFileName` 起始目录参数需 `str` 而非 `Path`
- GPT-SoVITS 应用自动启动 `api.py` 会用错 Python——文档明确要求**手动启动 API**（start-api-v3.bat）
