## 一、项目概览

Windows 本地桌面 AI 变声工具（PySide6 + Python 3.12，约 4000 行），功能：音色库 / 克隆音色 / 文字转语音(TTS) / 声音转换(VC) / 实时变声 / 历史记录 / 设置。中文界面，强调"音频不出本机"。

**引擎架构（关键设计）**：
- `app/engines/base.py`：Protocol 定义 `TTSEngine` / `VCEngine` / `RealtimeTransform`
- `app/engines/registry.py`：按"音色类型 + 引擎可用性"自动路由
- **演示引擎（无模型也能跑）**：`fallback_tts.py`（Windows SAPI，PowerShell COM）+ `fallback_vc.py`（自研相位声码器 DSP）
- **真实 AI 引擎（需用户自行安装）**：`gpt_sovits.py`（克隆 TTS，REST API）+ `rvc.py`（音色转换，rvc-python 或 CLI）
- 演示模式下 TTS=系统语音、VC=DSP 变调，**不改变音色**——用户以为"克隆失败"多为未装模型所致

**目录结构**：
```
app/core/      config、voices(音色库)、validation(质量校验)、audio_io(解码/导出)、dsp、history(sqlite)、jobs(任务队列)

app/ui/        main_window + 7 个页面 + widgets + theme + context

```

## 三、当前未解决问题（导入音频）🔴

> **已定位根因（最新进展）**：诊断脚本证明音频文件完全正常（解码 0.01s、校验通过），
> 问题出在**后台线程回调 GUI 的机制**——已修复，见下方“根因与修复”。

### 现象（用户报告，最新一轮）

1. **音色库页**（`voices_page.py`）：点“导入音频”选 wav 后**完全无反应**（无对话框、无错误、无保存）
2. **克隆音色页**（`clone_page.py`）：导入后**一直停在“校验中”**（`_analyze` 的后台 work 不返回）
3. 环境确认：wav 格式；`imageio_ffmpeg` 已安装（`F:\python\Lib\site-packages\imageio_ffmpeg\binaries\ffmpeg-win-x86_64-v7.1.exe`）；Python 3.12（`F:\python`，非 .venv）

### 诊断结果（用户已跑 `tools\debug_import.py`）

```
文件: E:\音频\元歌_无间傀儡_挑衅.wav  大小: 1.9 MB
[1] 解码成功: sr=44100, 时长=7.7 秒, 耗时=0.01s
[2] 校验完成: ok=True, 噪声=10/100, 人声占比=64%
```

→ 音频文件无任何问题；问题在应用内部。

### 根因（已确认）🔴

**`app/ui/context.py::ui_soon()` 的跨线程回调永远不执行。**

旧实现：
```python
def ui_soon(fn):
    def wrapper(*args, **kwargs):
        QTimer.singleShot(0, lambda: fn(*args, **kwargs))  # ← 从后台线程调用
    return wrapper
```
Qt 行为：**无接收者（receiver）的 `QTimer.singleShot` functor 重载在“调用线程”执行回调**。
后台线程（JobQueue 的 worker / `run_background` 的线程）没有事件循环，
→ 回调排队后永不执行 → 界面永远停在“校验中/分析中”、异步结果全部丢失。
这解释了所有页面导入无反应的现象（TTS/VC 生成的异步回调同样会失效，用户尚未测试到）。

### 修复（已实施）

`app/ui/context.py` 改为 **Qt 信号桥**（线程安全的标准做法）：
```python
class _UiBridge(QObject):
    _call = Signal(object)

_bridge = _UiBridge()  # 主线程创建（模块在主线程 import）

def _dispatch(payload):
    fn, args, kwargs = payload
    fn(*args, **kwargs)

_bridge._call.connect(_dispatch, Qt.QueuedConnection)

def ui_soon(fn):
    def wrapper(*args, **kwargs):
        _bridge._call.emit((fn, args, kwargs))
    return wrapper
```
`_UiBridge` 的线程亲和性是主线程；后台线程 `emit` 后，`QueuedConnection` 保证槽在 GUI 事件循环执行。
全项目唯一入口 `ui_soon`，修复一处即覆盖所有异步回调（JobQueue 与 `run_background` 都经它）。

### 易踩的坑（已踩过）
- **`QTimer.singleShot(0, fn)` 从后台线程调用会丢失回调**（无接收者重载在调用线程执行，后台线程无事件循环）——跨线程回调必须用 Qt 信号桥（`Signal` + `QueuedConnection`），见 `context.py::ui_soon`
- `threading.Lock` 不可重入——嵌套加锁会死锁，用 `RLock`
- `QFileDialog.getOpenFileName` 第 3 参数（起始目录）需为 `str`，不能传 `Path`
- GPT-SoVITS 自动启动用错 Python 解释器——文档已明确建议手动启动 API
- `data/voices/library.json` 是 2 字节 `[]`（音色库已空），用户需重新导入
